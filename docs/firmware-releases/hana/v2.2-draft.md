## What changes in v2.2

This is an incremental release, not a redesign. It retains the v2.1 Hana foundation and adds the following behavior present in the build #115 source.

### Keymap and typing
- Keep the unified `BASE` layer with macOS as the default mode and layout-shifted GUI/Alt behavior for Windows.
- Keep the `NUM`, `NAV`, `SET`, and `MOUSE` layers and existing keymap/combination workflow.
- Configure balanced mod-taps with a 200 ms tapping term and 175 ms quick-tap timing.
- Keep the Bluetooth profile controls, output toggle, mouse controls, and ZMK Studio unlock control in the keymap.
- Make the mod-tap, layer-tap, and Bluetooth-profile hold-tap behaviors runtime-editable and enabled by default through the Studio runtime-layer metadata. Actual Studio editing behavior remains part of validation.

### OLED and dongle controls
- Include dongle-central firmware for both 128×32 and 128×64 SSD1306 displays, as well as a no-display dongle-central build.
- Add a right-half key behavior to toggle the OLED.
- Add a BASE display-view cycle behavior.
- Add selectable timeout cycling for the dongle display and its supported timeout behavior.
- Retain OS-aware modifier labels and the existing layer/status OLED UI from the Hana configuration.
- Keep battery reporting dependent on telemetry actually being available; a dongle without a battery must not be represented as having a dongle battery percentage.

### Firmware variants built in #115
- Hana left-half BLE-central firmware with Studio support.
- Hana right-half BLE-peripheral firmware.
- Hana left-half BLE-peripheral firmware for dongle-central mode.
- Dongle-central firmware without display.
- Dongle-central firmware for 128×32 OLED.
- Dongle-central firmware for 128×64 OLED.
- Settings-reset images for the XIAO and nice!nano-compatible MCU targets.

## Compatibility and versioning
- v2.2 is intended as a backward-compatible minor update to the Hana v2.1 setup, not a Chocofi release and not a universal-dongle release.
- Keep the previous known-good v2.1 firmware available for rollback.
- The source commit is part of a multi-board repository history. This note documents only the Hana changes and Hana artifacts; it does not imply that the entire repository commit contains Hana-only files.
