## Overview

Hana is a wireless split keyboard configuration with standard split BLE operation and a dedicated USB dongle-central configuration. This release draft collects the intended feature set for the next stable Hana firmware release.

## Keymap and typing behavior

- Unified `BASE` layout with macOS as the primary/default OS mode.
- Persistent layout shift for macOS/Windows modifier behavior, avoiding separate base layers.
- Layer set: `BASE`, `NUM`, `NAV`, `SET`, and `MOUSE`.
- Existing combos retained.
- Balanced mod-tap/layer-tap behavior, including tap, hold, repeated tap, and tap-and-hold behavior.
- Recorded timing baseline: 200 ms tapping term and 175 ms quick-tap.
- Mirrored modifier/thumb-cluster behavior retained.
- NAV-layer OS-mode toggle retained.

## Mouse, Bluetooth, and Studio

- Mouse movement, scrolling, and mouse-button controls.
- Bluetooth host-profile controls and USB/Bluetooth output switching.
- ZMK Studio support.
- Runtime layer editing/reserved layer-slot work is part of the ongoing firmware workflow; confirm the exact shipped behavior against the release artifact before describing it as a guaranteed end-user feature.

## OLED and dongle behavior

- SSD1306 OLED targets for 128×64 and 128×32 displays.
- Dongle-central firmware with left/right Hana halves operating as BLE peripherals.
- Dongle status includes left/right peripheral battery reporting when supported by the connected hardware.
- OLED modifier labels follow the active OS mode:
  - macOS: Ctrl / Opt / Cmd / Shift
  - Windows: Ctrl / Win / Alt / Shift
- OLED status features and layer indicators retained.
- Intended display behavior includes OLED enabled by default on plug-in/wake, a right-half SET-key OLED toggle, selectable dongle display timeout, and half idle-sleep settings.
- Battery UI should only be shown when battery telemetry is actually available; do not show a dongle battery percentage for a dongle without a battery.
